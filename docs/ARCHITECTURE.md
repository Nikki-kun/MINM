# Архитектура приложения MINM

## Обзор

MINM (Messenger) - это многопоточное HTTP-серверное приложение для обмена сообщениями, построенное на C++ и Qt6. Приложение использует архитектуру с разделением ответственности между компонентами обработки сетевых запросов и бизнес-логики.

## Основные компоненты

### 1. HttpServer

**Назначение**: Основной компонент для приема и обработки HTTP-запросов.

**Ответственность**:
- Прием входящих TCP-соединений через `QTcpServer`
- Управление жизненным циклом сокетов
- Буферизация данных от клиентов
- Передача запросов в отдельный поток для обработки

**Особенности**:
- Работает в главном потоке приложения
- Использует `QTcpServer` для прослушивания порта
- Хранит активные соединения в `QMap<qintptr, QTcpSocket*>`
- Буферизует данные клиентов до получения полного HTTP-запроса

### 2. RequestProcessor

**Назначение**: Обработка HTTP-запросов в отдельном потоке.

**Ответственность**:
- Парсинг HTTP-запросов (метод, путь, тело)
- Извлечение JSON-данных из тела запроса
- Вызов соответствующих методов `MessageManager`
- Формирование и отправка HTTP-ответов

**Особенности**:
- Работает в отдельном потоке (`QThread`)
- Использует сигналы/слоты Qt для межпоточной коммуникации
- Обрабатывает запросы асинхронно через `QMetaObject::invokeMethod`
- Отправляет ответы через новый `QTcpSocket`, созданный с дескриптором сокета

### 3. MessageManager

**Назначение**: Центральный компонент бизнес-логики приложения.

**Ответственность**:
- Управление коллекциями контактов, чатов и сообщений
- Обработка HTTP-запросов и маршрутизация к соответствующим обработчикам
- Валидация данных
- Преобразование данных в JSON для ответов
- Генерация сигналов Qt при изменении данных

**API эндпоинты**:
- `GET /contacts` - получение списка контактов
- `POST /contacts` - добавление контакта
- `GET /chats` - получение списка чатов
- `POST /chats` - создание чата
- `GET /messages` - получение списка сообщений
- `POST /messages` - отправка сообщения (type: 0 — в чат, type: 1 — рассылка во все чаты)

**Особенности**:
- Хранит ссылки на векторы данных (не владеет ими)
- Использует сигналы Qt для уведомления об изменениях
- Поддерживает валидацию входных данных

### 4. Core Classes

#### Contact
Простая структура данных для представления контакта пользователя:
- `id` - уникальный идентификатор контакта
- `ownerId` - идентификатор владельца контакта
- `contactId` - идентификатор контактируемого пользователя
- `contactName` - имя контакта
- `addedDate` - дата добавления

#### Chat
Класс для представления чата с поддержкой многопоточности:
- `id` - уникальный идентификатор чата
- `type` - тип чата (PRIVATE, GROUP, CHANNEL)
- `participants` - список участников
- `messages` - список идентификаторов сообщений
- Использует `std::shared_mutex` для потокобезопасного доступа

#### Message<T>
Шаблонный класс для представления сообщения:
- `id` - уникальный идентификатор сообщения
- `sender_id` - идентификатор отправителя
- `receiver_id` - идентификатор получателя (chat_id, -1 для рассылки)
- `content` - содержимое сообщения (шаблонный тип)
- `timestamp` - временная метка создания
- `status` - статус сообщения (отправлено, доставлено, прочитано)
- `type` - тип сообщения (MESSAGE_NORMAL, MESSAGE_BROADCAST)
- Использует `std::mutex` для потокобезопасного доступа к статусу и содержимому

### 5. WidgetManager

**Назначение**: GUI-компонент для визуализации данных и отправки сообщений.

**Ответственность**:
- Отображение контактов, чатов и сообщений
- Фильтрация чатов по выбранному контакту (пользователь ID 0)
- Отправка сообщений в выбранный чат через `MessageManager::addMessage`
- Обновление интерфейса при изменении данных через сигналы
- Управление виджетами Qt (QTreeWidget, QTableWidget, QTextEdit, QLineEdit, QPushButton)

**Особенности**:
- Работает в главном потоке приложения
- Подписывается на сигналы `MessageManager` (contactAdded, chatAdded, messageAdded и др.)
- Использует ссылки на те же векторы данных, что и `MessageManager`
- Стили вынесены в `include/ui/styles.h` (namespace Ui)
- Реализация разделена на `widget_manager.cpp` (UI) и `widget_manager_handlers.cpp` (обработчики)

## Поток данных

### Обработка HTTP-запроса

1. **Прием соединения** (`HttpServer::onNewConnection`)
   - `QTcpServer` принимает новое TCP-соединение
   - Создается `QTcpSocket` и сохраняется в `m_sockets`
   - Подключаются сигналы для чтения данных

2. **Чтение данных** (`HttpServer::onReadyRead`)
   - Данные читаются из сокета и добавляются в буфер клиента
   - Проверяется наличие полного HTTP-запроса (по `\r\n\r\n`)
   - При наличии полного запроса данные передаются в `RequestProcessor`

3. **Обработка запроса** (`RequestProcessor::processRequest`)
   - Запрос парсится (метод, путь, тело)
   - JSON-данные извлекаются из тела запроса
   - Вызывается `MessageManager::handleRequest()`
   - Формируется JSON-ответ

4. **Отправка ответа** (`RequestProcessor::sendResponse`)
   - Создается новый `QTcpSocket` с дескриптором исходного сокета
   - Формируется HTTP-заголовок и тело ответа
   - Данные отправляются клиенту
   - Сокет закрывается

5. **Очистка** (`HttpServer::cleanup`)
   - После обработки запроса сокет удаляется из `m_sockets`
   - Клиент удаляется из `m_clients`

## Многопоточность

### Архитектура потоков

1. **Главный поток (Main Thread)**
   - Запуск приложения (`QApplication`)
   - Управление `HttpServer` и `WidgetManager`
   - Обработка событий Qt

2. **Поток обработки запросов (RequestProcessorThread)**
   - Обработка HTTP-запросов
   - Вызов методов `MessageManager`
   - Доступ к данным через мьютексы в `Chat` и `Message`

### Потокобезопасность

- **Chat**: Использует `std::shared_mutex` для защиты `participants` и `messages`
- **Message**: Использует `std::mutex` для защиты `status` и `content`
- **Межпоточная коммуникация**: Используются сигналы/слоты Qt с `Qt::QueuedConnection`

## Структура данных

### Хранение данных

Данные хранятся в векторах, созданных в `main()`:
- `QVector<Contact> contacts` - список контактов
- `QVector<std::shared_ptr<Chat>> chats` - список чатов
- `QVector<std::shared_ptr<Message<std::string>>> messages` - список сообщений

Эти векторы передаются по ссылке в `MessageManager` и `WidgetManager`, обеспечивая общий доступ к данным.

### Идентификаторы

- `user_id` - идентификатор пользователя
- `contact_id` - идентификатор контакта
- `chat_id` - идентификатор чата
- `message_id` - идентификатор сообщения

## Зависимости

- **Qt6**: Core, Widgets, Gui, Network
- **C++20**: Используются современные возможности языка
- **STL**: Используются стандартные контейнеры и мьютексы

## Расширяемость

Архитектура позволяет легко добавлять:
- Новые HTTP-эндпоинты через добавление методов в `MessageManager`
- Новые типы данных через создание соответствующих классов
- Дополнительные потоки обработки через создание новых `QThread`
- Новые GUI-компоненты через расширение `WidgetManager`
